# Phylode

> English: [README.md](README.md)

給 Apple 家庭的網路守門員。家裡任何設備上網時，它先把廣告、追蹤、詐騙網站和家電往外亂連擋掉；Apple 的服務一律放行。

名字由希臘文 *phylax*（守護者）和 *ōidē*（頌歌）組成：守護者之歌。

## 狀態（2026-09-30）

**骨幹會動了，安全硬化做完前六項；一份全專案審查的每一條發現都已修好或列入待辦。**

能跑的：擋網址、走加密上游轉發、答案快取、查詢紀錄、放行清單、
`allow`／`block`／`status`／`report` 指令、開機自動啟動的部署檔、
**自我健康檢查**（卡住但沒退出時自己重啟）、
**防 DNS 重新綁定**（外面回來的答案指向家裡內網就整筆丟掉）、
**資源上限**（每台設備每分鐘 1000 次、同時問上游 300 筆、TCP 同時 10 條）、
**同一個網址同時只問上游一次**、
**DNSSEC 先記錄不阻擋**（簽章驗不過的照常打得開，本週重點記下次數與網址）、
**上游壞了自動重新探測**（修好就排回原位）、
**套件漏洞檢查**（`cargo deny check`，規則在 `deny.toml`）、
**封鎖名單每天自動更新**（Hagezi Pro ＋ 威脅情資 TIF，約 106 萬個網域，驗過筆數才換上、留上一版備份）、
**擋 CNAME 偽裝**（名字本身乾淨、別名指向追蹤商的也擋）、
**家裡內部的名字不送出去**（`.local`、路由器的搜尋網域、私有位址反查當場回答）。
**上游憑證用 macOS 系統信任庫驗**（根憑證跟著系統更新）、**「查無此網址」也會記住**（最多 1 小時）、
**每週重點自動存檔保留 12 週**（存檔不含一般放行的網址）。
自己寫約 9000 行，直接依賴 10 個（`Cargo.lock` 共 182 個套件），175 則測試。

**模糊測試**：四個入口（家裡設備送來的封包、上游回來的封包、封鎖名單、設定檔），`fuzz/` 底下，由 GitHub Actions 工作流程執行；最近一輪每個入口各跑 10 分鐘，合計 1.14 億筆，沒有崩潰也沒有卡住。

**還沒做的**（下一輪照這個順序）：封包層驗證、macOS 沙箱。

## 做得到什麼（都實跑驗證過）

```
$ dig @127.0.0.1 iadsdk.apple.com
iadsdk.apple.com.  2  IN  A  0.0.0.0      ← 被擋（Apple 廣告，在 Hagezi 名單上），TTL 2 秒

$ dig @127.0.0.1 apple.com
apple.com.  165  IN  A  17.253.144.10     ← 走加密上游拿到的

$ dig @127.0.0.1 這個網址不存在.com
;; ->>HEADER<<- status: NXDOMAIN          ← 上游說沒有，原樣轉達，附 SOA

$ dig @127.0.0.1 192.168.0.1.nip.io
;; ->>HEADER<<- status: NOERROR, ANSWER: 0  ← 這個網址會解析到家裡內網，
192.168.0.1.nip.io.  2  IN  SOA  ...           整筆答案丟掉（防 DNS 重新綁定）

$ phylode allow doubleclick.net
已放行 doubleclick.net，幾秒後生效。想收回就打：phylode block doubleclick.net

$ phylode report
守門員這週（2026-09-14）
1. 擋下 2 次（總查詢 4 次）
...
6. 有沒有一段時間其實沒有保護
   沒有，全程都有保護。
```

## 幾個刻意的設計

- **連不上就不降級。** 加密上游全部連不上時，用快取的舊答案撐住，**絕不改用未加密查詢**。
  依據是 RFC 8310 的 Strict Privacy，也是 Apple 加密查號台的出廠預設。
  這條做進型別：程式碼裡根本沒有「明文查詢」這個選項。
- **絕不回「拒絕服務」。** 那會讓設備立刻重試造成風暴，而且會讓它改去問名單上的下一台查號台，
  過濾當場失效。`Response` 型別沒有那個變體。
- **「這個網址不存在」是答案，不是失敗。** 型別把兩者分開（`Answer` vs `Err`），
  所以打錯的網址會拿到正確的 NXDOMAIN，而回答正確的上游不會被誤記成掛掉。
- **卡住但沒退出時自己重啟。** 每 10 秒對自己的監聽埠送一筆真的查詢走完整條路，
  連續兩次沒回應就把原因寫進紀錄再結束行程讓系統接手。開機服務的監督只看行程在不在，
  抓不到「還活著但答不出東西」。
- **外面回來的答案指向家裡內網，整筆丟掉。** 那是拿惡意網域把瀏覽器變成攻擊內網跳板的手法。
  一批答案裡只要有一個內網位址就整批不要——攻擊者會混一個公網位址進來，賭我們只過濾單筆。
  真的屬於家裡的網域列進設定檔的 `internal_domain` 就放行，預設一個都沒有。
- **名單掛掉時放行，而且那次放行不進快取。** 進了快取，名單恢復後那個網域仍會擋不掉。
- **`captive.apple.com` 與 `push.apple.com` 寫死在程式裡，任何情況都通。**
  擋了前者，全家 Apple 裝置會一直跳登入視窗；擋了後者，推播與 iMessage 失效。
- **服務不用 root。** launchd 綁 53 埠再把 socket 交過來（Apple 原生的 socket activation）。
- **回答網址的路徑上零檔案 I/O。** 紀錄丟進有界的管道，由專責執行緒批次寫硬碟。
- **沒有任何控制通道。** 指令只編輯純文字檔，不開網路埠也不開 unix socket。

## 第一版不做

所有流量穿過守門員、出門在外的保護、圖形介面、任何形式的資料回傳。

## 技術

Rust，跑在 macOS 上。協定層用 hickory（被第三方稽核過、Let's Encrypt 與 Google Pixel 在用），
藏在自己的薄介面後面；政策、快取、紀錄、報告、設定、指令列全部自己寫。
這個取捨的依據：DNS 函式庫值得依賴，因為封包格式的正確性是它的專業；但過濾行為是這個產品本身，不能藏在別人的抽象裡。

整個專案 `deny(unsafe_code)`，唯一的例外是接手 launchd 描述子的那兩行，
有測試數著例外的數量，多一個就讓建置失敗。

## 安裝

需要 macOS 與 Rust 工具鏈（[rustup](https://rustup.rs)）。在 Apple 晶片的 macOS 26、27 上測過；
每次改動都會在 CI 上把安裝腳本從頭到尾實跑一次。

```bash
cargo build --release
sudo ./deploy/install.sh
```

移除：`sudo ./deploy/uninstall.sh`（會先把系統查號台改回自動取得再停服務）。
